Authority: the user's approved continuation request and saved Figma English desktop contexts under `verification/reference`. This is a frontend-only preview, not an authentication or authorization service. No remote write, billing, deletion or real account lifecycle is implemented.

## Data and workflows

The user's latest landing screenshot supersedes the blank-root requirement. `/` is a public landing page: signup calls to action open `/signup`, visitor links open `/community`, and About retains the shared, dismissible unavailable-page notice. It reuses Navbar's visitor/member behavior without changing authentication or permission rules. The shared AR/EN selector updates the interface and document direction immediately and persists the preference. Home visitor information appears below the navbar and stays dismissed across ordinary rerenders. `tests/browser/landing.spec.mjs` checks eight viewport widths, navigation, assets and accessibility.

- CommunityProvider owns in-memory sample questions and per-question answers, plus per-account reactions and drafts. Reload clears changes. Saved Figma counters include discussion content that was not supplied; the UI explains partial fixtures instead of inventing missing answers.
- Normal sign-in uses the four documented demo credentials. No query parameter or role selector grants a session. The adapter requires explicit mock configuration and, in production, explicit public-demo intent. Session storage holds only a fixture ID and curated completion/skill flags, never credentials or personal form data. Temporary signup and its credential comparison hash remain in memory only.
- Visitor reactions/opening Ask prompt sign-in. Direct protected-route navigation redirects to sign-in with a validated internal return destination. Member preview submissions update local state synchronously and navigate to the resulting question. No fake network spinner or real server success claim is used.
- Question title minimum 15 trimmed characters, body minimum 30, and 1–5 tags. Answer requires nonempty text. All errors are inline and associated with their controls.
- Save as draft retains title/body/tags in memory. Cancel also retains the draft and returns to the feed. Posting clears it. Reload-loss is disclosed. A submitted answer belongs only to its question; changing question IDs clears the unsubmitted answer composer.
- Markdown is deliberately limited to fenced code, lists and HTTP(S) links. React escapes raw HTML. External links use noreferrer. No HTML insertion or executable URL scheme is accepted.
- Search/category/tag/sort/visible count are URL-backed and restore on Back. Category matches exact IDs; unanswered means zero answers. Counts shown without filters reproduce the original fixture totals; filtered counts describe available sample records.
- Navbar mobile disclosure is not a modal: ordinary Tab order, no focus trap. Opening reveals all links/actions, Escape returns focus, route selection and crossing 1024px close it. Account links remain inside mobile disclosure. The desktop account disclosure shares Escape behavior.
- Profile uploads validate PDF/DOCX size and retain metadata only. Native file and select pickers are deliberately OS-owned. There is no upload API.
- No destructive data operation exists. Obsolete components may be removed only after import searches and replacement checks. Pre-existing repository deletions and Git history stay untouched.

## Verification scope

Problems additions: `ProblemsProvider` owns per-user/per-problem drafts and one local submission per user/problem, plus per-problem comments. All are memory-only and reset on reload. Save and Cancel retain a draft; successful local submission clears the draft. Duplicate submissions are disabled and guarded in the store. Files retain name/size only; PDF/DOCX up to 5MiB and nonzero size are accepted. Original reference attachments report their unavailability rather than downloading fabricated data.

The canonical Textarea now supports an opt-in `autoGrow` variant used by problem comments and proposals. It starts at 132px and recalculates on content and viewport changes; manual resize is disabled. The existing default behavior and ref forwarding remain available to Community and other consumers.

Demo identities are member, incomplete solver, eligible solver and company, selected only through credentials. The central permission model separates technical/company role, profile completeness, selected skills and problem skill intersection. A complete technical profile authorizes the demo form; skill intersection is illustrative, not AI or a production matching rule. Client guards are not a security boundary. Profile completion persists only curated fixture flags in session storage and can return to a validated Problems detail path; ordinary onboarding goes to Account Activated. Normal production disables mock login; intentional public demo builds must explicitly set both documented flags.

Summary and delivery are required; 50 words is a recommendation, not a hard validation threshold. Optional links accept only absolute HTTP(S) URLs. Original-work consent is required. The terms document itself was not supplied, so no invented legal content is linked. The form's screenshot wording about sending to a company is accompanied by an explicit local-preview disclosure and a modal that confirms no transmission occurred. No requests, artificial loading spinners, backend persistence, AI matching, company review, acceptance or payment workflow is simulated.

List totals reproduce Figma's static fixture totals; only four problem records exist. The Show more action explains the limited dataset. Comments require a demo member/solver/company; visitors receive the existing auth prompt. Reply targets are local, text is React-escaped, changing problem IDs resets the composer, and comments remain attached to the correct problem. Other list records have only their supplied summaries and a missing-requirements disclosure.

`tests/browser/frontend.spec.mjs` supersedes the historical URL-preview verification scripts. It signs in through the form and captures all current screen/state combinations at 320×600, 375×812, 430×932, 768×1024, 1024×768, 1280×800, 1440×1040 and 1920×1080. It exercises menu keyboard/Escape/resize/navigation, filtering, draft isolation, file validation, local submission, route guards, profile completion, short-laptop content and the landing route. Generated results and screenshots remain local under `verification/final/`. Historical evidence is preserved but is not presented as a current passing run.

Chromium at widths 320, 375, 430, 768, 1024, 1440 and 1920, including 600px-tall viewports. `verification/application-responsive.mjs` captures screenshots and checks visibility, navigation, overflow, assets, dialog focus, filters, drafts, questions and answers. Desktop layout checks use saved properties because original application-frame PNGs are missing. Mobile behavior is an adaptation, not a claimed Figma mobile reproduction. No backend async/failure or native mobile-device certification is implied.
