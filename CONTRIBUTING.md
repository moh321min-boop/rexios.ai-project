# Contributing to RexiosAI Project

Thank you for your interest in RexiosAI.
This repository is currently documentation-first. Source code will be added
to this same repository in a later phase.

---

## 1. Who Can Contribute

There are two groups of contributors.

### Core Team

- Selected from the community.
- Can commit directly to the `main` branch.
- Reviews Pull Requests from external contributors.
- Each member focuses on a specific area (documentation, frontend, backend,
  AI, design, etc.).
- Membership is based on contribution, not on title.

### External Contributors

- Anyone from the public.
- Cannot commit directly to `main`.
- Must submit changes through a Pull Request (PR).
- PRs are reviewed by the Core Team before merging.
- Consistent contributors may be invited to the Core Team.

---

## 2. What You Can Contribute

At this stage, contributions are documentation-only. This includes:

- Fixing typos or unclear wording.
- Improving explanations.
- Adding missing details to existing documents.
- Proposing new documentation files.
- Reporting inconsistencies between files.

Code contributions are not accepted yet. This will change once the
codebase is added to this repository.

---

## 3. How to Contribute

### Step 1 — Fork the repository

If you are an external contributor, fork the repository to your own GitHub
account.

### Step 2 — Create a branch

Use a clear branch name:

- `docs/short-description` for documentation changes.
- `fix/short-description` for corrections.
- `proposal/short-description` for new ideas or structure.

Example:
docs/improve-readme

### Step 3 — Make your changes

- Edit only documentation files (`.md`).
- Keep changes focused on one topic.
- Follow the existing style and structure.
- Do not add code files, binaries, or large assets.

### Step 4 — Commit your changes

Use clear commit messages with a short prefix:
docs: fix typo in README
docs: clarify MVP features
fix: correct broken link in STACK
proposal: add new section to ROLES

### Step 5 — Open a Pull Request

- Describe what you changed and why.
- Link any related issue if available.
- Wait for review from the Core Team.

---

## 4. Review Process

1. A Core Team member reviews the Pull Request.
2. Feedback may be given.
3. Once approved, the PR is merged into `main`.

External contributors cannot merge their own PRs.
Core Team members can commit directly to `main` but should still open PRs
for large changes.

---

## 5. Branch Naming

| Type | Prefix | Example |
|---|---|---|
| Documentation | `docs/` | `docs/update-roadmap` |
| Fix | `fix/` | `fix/broken-link` |
| Proposal | `proposal/` | `proposal/new-section` |

---

## 6. Commit Message Style

Use short, clear messages with a prefix:

| Prefix | Meaning |
|---|---|
| `docs:` | Documentation change |
| `fix:` | Correction |
| `chore:` | Maintenance |
| `proposal:` | New idea or structure |

Examples:
docs: add stack overview
fix: correct typo in CONTRIBUTING
chore: reorganize file order
proposal: add glossary section

---

## 7. When to Update CHANGELOG.md

- Update `CHANGELOG.md` only for significant changes.
- Small fixes (typos, formatting) do not require a changelog entry.
- Significant changes include:
  - Adding a new file.
  - Changing the project structure.
  - Updating the scope or direction of the project.
  - Updating the license or roles.

Note: `CHANGELOG.md` does not exist yet. It will be created in a later phase.

---

## 8. What Not to Do

- Do not add code files at this stage.
- Do not add binaries, images, or large files.
- Do not include secrets, tokens, or personal data.
- Do not make unrelated changes in one Pull Request.
- Do not edit files outside the scope of your contribution.
- Do not rename or delete existing files without prior discussion.
- Do not rewrite entire documents without justification.

---

## 9. Code of Conduct

- Be respectful.
- Assume good intent.
- Give constructive feedback.
- Focus on ideas, not people.
- Avoid personal attacks or dismissive language.
- Report serious issues to the Project Maintainer.

---

## 10. Questions

If you are unsure about anything:

- Open an issue.
- Ask a Core Team member.
- Wait for clarification before making large changes.

Small fixes can be submitted directly as Pull Requests.
Large changes should be discussed first.

---

## 11. Summary

| Action | Who |
|---|---|
| Commit directly to `main` | Core Team |
| Submit Pull Request | External Contributors |
| Review Pull Requests | Core Team |
| Approve large changes | Project Maintainer |
| Update CHANGELOG | Anyone, for significant changes |
